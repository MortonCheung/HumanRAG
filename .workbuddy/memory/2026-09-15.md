# 2026-09-15 HumanRAG V11 收口复核（测试门禁可靠性）

承接 09-14 的收口，本轮做的是**复核 + 让门禁可复现**，产品体验无改动。

## 本轮完成

- 复核 09-14 的悬案：入场镜头「没拉开」是**探针假象**——`data-spatial-camera` 只在 CameraControls 的 `rest` 事件发布，而入场期间 `controls.enabled === false`，`rest` 永不触发，E2E 整段读到同一个旧值（168 帧同值）。镜头本身一直是正确的（60.85 → 118.01）。
- 修掉**测试自身**两处不可靠：
  1. `src/scene/CameraController.tsx` 相机位姿改为逐帧发布（`useFrame`）——此前「方向不翻」断言实际是空断言。
  2. `e2e/opening-entry.spec.ts` 的拉开幅度原本拿「入场后第一帧」当基线，而第一帧落在哪一刻受主线程负载影响（同一份正确实现实测会读到 60.85 或 78.9，比值 1.94 / 1.50 恰好跨过 1.5 阈值 → 随机失败）。改为安装探针时**同步**抓一帧 seed 位姿（点击之前），并取整段轨迹的 min/max。
- 修掉**真实产品缺陷**：同一目标重复「生成知识树」必定失败——`GoalTreeComposer` 树名/范围确定性 → 第二次撞 `createTree` 同名校验 → 抽屉只显示通用「没能整理这棵知识树」。新增 `resolveGoalTreeTarget()`：同名同范围复用已有树、同名不同范围去重，任何情况下不再中断提取。
- **E2E 串行化**：`playwright.config.ts` 的 `workers` 由「仅 CI 为 1」改为**恒为 1**。

## 关键结论：E2E 并发抖动 ≠ 产品回归

- 症状：`--workers=2` / `4`（本机 8 核 → Playwright 默认 4 worker）下 `readonly-preview`（verify）与 `responsive`（mobile）偶发 30s 超时；报错点落在 `page.mouse.move` / `page.evaluate`。
- 根因：渲染走 SwiftShader **软件光栅**，而知识树预览是**常驻自转**的 WebGL 场景；并发把 CPU 打满，CDP 指令排不上渲染主线程。
- 判据（下次直接套用）：30s 超时 + 报错在上述 CDP 指令上 + 单独跑 3–4s 通过 ⇒ 判**并发抖动**，不要据此改回旧文案/旧实现。
- 处理：串行后 `npm run test:e2e` 稳定 **48 通过 + 1 跳过，0 失败**。
