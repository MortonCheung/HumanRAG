### 0.1 本次要交付的产品

HumanRAG 是一个由个人目标驱动、以知识树组织范围的定向教学产品。用户可以探索知识空间、选择目标、暴露具体困难、接受有针对性的教学，然后独立完成新任务。

核心路径固定为：

```text
选择目标 → 尝试任务 → 判断困难 → 找到相关内容
                                     ↓
更新下一步 ← 留下学习证据 ← 独立完成新任务 ← 讲解与互动示范
```

三维空间承担吸引、导航、关系理解和学习状态反馈；教学工作区承担理解与能力形成。两者共享知识对象与真实记录。

### 0.2 必须同时达成的四项结果

1. 美术：开场和知识空间具有明确主体、大尺度构图、细致材质与克制界面，静止截图也成立。
2. 动画：关键过程有来源、运动和去向，能连续、能中断、能恢复，不依赖满屏特效制造存在感。
3. 逻辑：按钮有固定归属，返回有确定父层级，编辑不会覆盖用户刚刚完成的操作。
4. 教学：不同困难得到不同教学，辅助下答对与独立完成被区分，结果能改变下一步建议。

四项分别验收，不能用其中一项的完成抵扣另一项。

### 0.3 本轮不扩展的范围

- 不新增独立的全局“教学首页”“刷题首页”或聊天机器人首页。
- 不扩成所有专业、职业规划平台、社交学习平台或课程交易平台。
- 不预先选择比赛赛道，不替用户报名，不保证获奖。
- 不新增账号系统、付费模型、向量数据库、云端同步或多人实时编辑。
- 不重写现有数据层，不因更名清除本地记录，不批量更换路由与存储键。
- 不复制参考网站的品牌、宣传内容、专有模型、音乐或未经许可的源码。
- 不以大量自动生成的模板知识点代替完整教学内容。

## 1. 先锁定不能再变形的产品规则

### 1.1 信息层级与共享工作区

产品层级只有：知识库（领域）→ 知识树（方向）→ 知识点（最小教学与出题单位）。当前只实现计算机知识库。

- 目标是选择与组织学习范围的依据，不是新的一层知识对象。
- 不恢复旧版“目标、方向、技能、课程、知识、练习”六层产品结构。旧数据中的类型可作为兼容字段，不能重新支配页面层级。
- 教学内容和题目绑定知识点。树题库、库综合题库只聚合并去重，不复制题目。
- 从 Universe 和知识库进入同一知识点，复用同一 `LearningWorkspace`、`PracticeWorkspace` 与学习记录。
- 知识树默认进入使用状态。点击一次“编辑”后，选中节点即可编辑，不再要求第二次进入节点编辑模式。
- 用户可随时更换目标；旧学习证据保留，不因目标变化归零。

这里的 `LearningWorkspace`、`PracticeWorkspace` 是共享工作区的职责名称。当前仓库实际由 `TeachingSessionPage`、`PracticeSessionPage` 承接相应路由，尚不存在旧 V9 文档规划的两个同名文件。优先演进当前共用页面，不为对齐文档命名再复制页面。

### 1.2 HumanRAG 的解释边界

品牌沿用“从已有知识中找到与当前目标有关的内容，再改变下一次行动”的想法。

实现与展示必须区分：系统检索资料、用户回忆知识、用户理解知识、用户独立应用知识。这四件事不是同一件事。

不使用“像训练神经网络一样训练人脑”“从本质上重构大脑”“检索完成即掌握”等科学性断言。界面中的“推荐”或“针对性教学”必须能追溯到实际目标、作答与内容选择。

当前若使用规则和本地内容，演示中应明确说明。不能因目录名包含 `ai`，就把它描述成已经运行的生成式模型或语义向量检索系统。

## 3. 美术总纲：画面丰富，界面干净

### 3.1 单一视觉方向

拟定方向：暗色、雕塑感、带真实空间深度的知识结构。

主角是由实际知识点与关系构成的结构体。根部、分支与细节具有尺度差；柔和方向光刻出轮廓，局部连接在操作发生时变得清晰。画面大、主体完整，控件像精密工具一样稳定。

不使用这些默认套路：黑底彩色发光球、紫蓝渐变标题、满屏小卡片、随机粒子、四角参数装饰、无意义英文标签、玻璃面板层层套叠、自定义鼠标、全站视差或滚动劫持。

视觉力度按区域分配：

| 区域 | 视觉与动态的职责 |
| --- | --- |
| 开场 | 最强构图与完整运镜，是作品级展示窗口 |
| Universe | 保留空间张力，用户操作优先，背景安静 |
| 知识库与编辑 | 大幅展示知识结构，控件准确，减少持续运动 |
| 教学 | 示范对象可以强动态，题干与输入保持稳定 |
| 练习与记录 | 阅读优先，变化只用于状态反馈 |

### 3.2 颜色与材质基线

沿用现有 CSS 变量体系，统一修改 token，不再叠加 `v10-*` 覆盖补丁。

| 语义 | 拟定值 | 用途 |
| --- | --- | --- |
| 深背景 | `#080B0D` | 页面与远景 |
| 基础表面 | `#101518` | 顶栏、阅读区 |
| 抬升表面 | `#171E22` | 预览、菜单、输入 |
| 悬停表面 | `#202A2F` | 控件悬停 |
| 主文字 | `#EDF2F0` | 标题、主要信息 |
| 次文字 | `#AFBAB6` | 辅助信息、非活动标签 |
| 弱文字 | `#84928D` | 次要元信息；仍要测对比度 |
| 单一强调色 | `#B1D8CA` | 选中对象、主要按钮、当前路径 |
| 普通分隔线 | `rgba(237,242,240,.10)` | 区域分界，不代替控件边界 |
| 控件边界 | `#67756F` | 必须被识别的输入、焦点外形 |
| 错误 | `#E0A497` | 有文字/图标共同说明的错误 |

说明：这是建议从当前暖金偏绿黑转向冷炭黑与浅青玉色的统一方案，须在关键画面确认后锁定。已有用户自定义节点颜色保留为内容属性，降低非选中展示的饱和度，不批量改写用户数据。错误、成功是语义状态色，不扩成第二套品牌色。

材质约束：

- 根节点以有明确轮廓的低复杂度实体为主；分支使用同族简化形体；知识点保持小而清晰的节点形体。
- 比例、切面和粗糙度构成识别差异，不给每个节点设计一套模型。初始建议根/分支/知识点的视觉直径比例约为 `3 : 1.8 : 1`，经屏幕可读性验收调整。
- 使用一个主方向光和低强度环境补光。轮廓清晰，不出现一圈吞掉形体的白光。
- 普通关系线在 1080p 下可辨但不抢眼；选中路径通过线宽、明度和有方向的一次性推进形成层级。
- 背景明暗渐变只表达空间和照明，不是彩色营销渐变。
- 不把景深、噪点、折射、色散、泛光同时打开。首版以几何、灯光和构图成立为先，泛光是可关闭的末级修饰。

### 3.4 图层与响应式

只定义一套图层语义：场景 `0`；正文/场景标签 `10`；停靠面板 `20`；顶栏 `30`；菜单 `40`；模态遮罩/对话框 `50/60`；短暂通知 `70`。父级不再随意制造更高 stacking context。

装饰层和退出中的视觉副本必须 `pointer-events: none`；视觉副本同时退出辅助技术树。不要用透明大按钮扩充热区。

断点按功能转换：

- `≥1280px`：完整桌面构图，右侧预览宽 340px，编辑属性区宽 360px。
- `1024-1279px`：预览/属性区宽 300-320px；长标题截断；低频命令收进同一顶栏菜单。
- `768-1023px`：图与信息分时突出，侧面板可覆盖右侧，打开时重新计算镜头安全区。
- `<768px`：单列；预览采用可关闭的底部面板或独立内容区，编辑采用“画布/属性”模式切换，入口仍位于原顶栏，不能多造第二条导航。

全屏空间页使用动态视口高度并正确计算顶栏与安全区；内容页允许自然滚动。浏览器地址栏变化不得截掉主按钮。不是所有页面都强制一屏塞完。

## 4. 唯一上下文顶栏

### 4.1 结构与职责

统一一个顶栏壳，三段职责固定：左侧为应用切换与父层级返回，中间为当前对象/模式，右侧为当前页面命令。

- 根页面左侧显示 HumanRAG 应用菜单，包含“知识空间”“知识库”。子页面在同一区域显示明确父级返回，应用菜单保持可达。
- 中间不同时堆标题、面包屑、说明文字和另一排页签。宽屏可显示短标题与模式组，空间不足时把模式组收为一个菜单。
- 右侧命令按“当前任务动作 / 查看工具 / 更多”分组，组内位置稳定。
- 使用可收缩三列 Grid；两侧预留对称空间，使标题在宽屏视觉居中。返回按钮本身必须 `justify-self: start`、内容宽度、最小 44px 热区，不能继承整列可点击宽度。
- 1024px 放不下时收纳，不换成两行。移动端保留返回、标题、当前主动作与更多菜单。

“全部统一到导航栏”在这里解释为：所有全局和页面级命令统一到这一个顶栏。答案输入、提交、提示、图形播放等属于内容操作，放在对应题目或示范对象旁边；它们不能被做成第二排页面导航，也不能在顶栏与内容区重复出现。

全屏使用浏览器实际 Fullscreen 能力，以 `fullscreenchange` 更新状态；请求被拒绝则保留页面、给出“未能进入全屏”。不支持时菜单说明不可用，不伪装成把相机拉远。

1. 页面“返回”：按上表，不依赖来源。
2. 流程“上一步”：回到当前创建流程的上一操作步骤，保留草稿。

## 5. 页面施工规格

### 5.1 开场：一个有体量的知识结构

当前问题：标题与场景关系弱，整体缺乏明确视觉主体；已有持久 Canvas 是基础，但固定延时切路由没有建立完整开场编排。

目标构图：

- 1440 × 900 基准画面，顶栏 64px。左侧内容约占可用宽度 32%-36%；知识结构占右侧 60%-64%，主体可越过中线，但不盖住文案和按钮。
- 主体不是角落缩小的图谱预览。其可见包围框高度占顶栏下空间约 68%-82%，前、中、后景均有可读轮廓。
- 选择实际知识图中的一个稳定根/分支作为近景，真实关系构成延伸结构。用相机取景与材质层次组织画面，不生成假数据充当装饰。
- 首版文案只保留品牌 HumanRAG、标题“学会你想做的事”、按钮“进入知识空间”。不再附“AI 教学系统”与“选择知识点、查看关系……”说明句。若可用性测试证明定位不清，最多增加一句事实性短说明，并重新审查首屏密度。
- 标题与按钮在首屏可见，不做巨型滚动品牌字、功能卡片墙、数据战报或假用户背书。
- 内容位置按照构图确定，不将文字分别散在四角。小屏改为上方标题、中央主体、下方按钮；主体不能压住按钮。
- 默认静音，不新增音频依赖。

开场动画按第 6 节完整执行。直接访问 `/universe` 不强制绕回首页看动画。

### 5.2 Universe：空间为主，工具归位

- 顶栏下整个区域是可操作场景，无重复标题、下方工具条和固定装饰底栏。
- 没有选中节点时不常驻大说明面板；搜索与目标入口只在顶栏。
- 悬停节点 120ms 后，信息进入右侧固定预览位。快速掠过不逐个闪卡；离开 160ms 后可收起未锁定预览。
- 点击节点锁定该预览并展开同一个对象；选择状态与悬停状态分别管理。移动端第一次点击即选择并打开预览，不依赖悬停。
- 已锁定 A 时，悬停 B 可以产生轻量视觉强调，但不得偷偷把 A 的内容替换成 B；点击 B 才正式切换。
- 预览内容默认只有名称、必要的一句定义、所属树、基于真实证据的当前状态。一个“开始学习”主按钮，练习作为次操作。无内容时不显示假入口。
- 关闭预览恢复原安全区，不重置用户相机。不移动其他树来腾位置。
- 同一固定区域不同时叠加节点详情、目标说明、学习路径和历史四张卡。打开模态工具时暂停场景拾取。
- 标签按屏幕密度筛选，选中/聚焦标签优先且不可被降级隐藏。相互遮挡时用稳定列表/搜索消歧，不让前景透明对象挡死后景节点。

目标工具采用已有目标数据做选择。应用目标后，强调相关知识和可解释的下一步；其他知识保持所在位置。不得用随机百分比或不透明的“AI 为你规划”文案替代实际依据。

搜索复用既有搜索能力，Universe 范围为全库，树内搜索限定本树。支持名称、已存在别名/关键词、键盘上下选择和回车定位。无结果只显示“没有找到相关知识点”，保留输入；不在本轮无边界引入语义搜索服务。

### 5.3 知识库：一页展示一个领域

- 大标题只写“计算机科学”。删除其下复述人工智能、前端、网络等范围的说明小字。
- 宽屏以左侧树目录和右侧大结构展示组成页面，目录约占 28%，展示约占 72%。不把每棵树塞成一组同尺寸小卡片。
- 当前树名称只在需要区分对象的地方出现一次，不在标题、预览标签、卡片标题重复三遍。
- 图形以包围框居中并留约 15%-20% 余量；不同规模树拥有相近的可读占屏量，而非使用同一相机距离导致大小悬殊。
- 单击目录项更新同一个展示区域；明确的打开动作进入该树。键盘可选择和打开，不要求双击。
- 切树保留展示容器，结构之间连续过渡；不能因 `key={tree.id}` 反复销毁整个 Canvas 后交叉淡入两个渲染器。
- 空知识树不展示假节点；系统树与个人树用必要的分组/标记区分，不增加大段管理说明。
- 若只含一棵树，保留简洁选择方式，不制造空白占位卡凑数量。

### 5.4 单知识树：默认使用，按对象进入

- 初次打开显示可选中的知识结构，不再放“选择知识点”大文案和“查看知识点”按钮，让用户再进入一层才看到真正入口。
- 总览、学习、题库为同一顶栏的模式，不是三个重复首页。
- 总览点选节点使用与 Universe 一致的预览行为和入口。
- 学习模式展示此树的知识点和一个有依据的建议起点；不再复制全部课程营销介绍。
- 题库模式展示范围、题量和开始条件；筛选知识点会影响同一个聚合题池。
- “编辑”在顶栏固定位置。进入后沿用当前节点选择与观察方向；退出回总览，保留用户摆放。

### 5.5 编辑器：选中即编辑，保存有边界

- 桌面画布占除右侧 360px 属性区之外的主要空间，不在画布上方再铺工具栏。
- 顶栏提供节点/题目/设置模式。节点模式中，选中节点后右侧直接出现名称、类型、内容和关系字段。
- 不显示“你可以编辑节点的内容与关系”等说明段。字段名、分组和当前选中状态自己表达用途。
- 无选中节点时只显示“选择一个节点”，不展示一整页禁用表单。
- 关系编辑提供目标搜索与当前关联结果。禁止自连；先修关系不得形成循环；删除不存在目标等情况在提交前校验。普通相关关系是否双向沿用现有模型，不发明新关系语义。
- 节点拖动松手提交位置；内容表单按“保存”提交。两种保存不能相互覆盖，详细契约见第 8 节。
- 改变选中节点、切换编辑模式或退出时，脏草稿不能静默消失；保存、放弃、取消离开的文案必须明确。
- 设置中的删除是明确危险动作，仅影响解析出的对象范围；确认中展示树名/节点名和影响，不放在画布角落，不一键删除整个库。
- 小屏通过顶栏切换画布/属性，属性使用完整宽度。操作同一个节点，不创建一套移动端数据状态。

### 5.6 创建知识树与知识点

新建树保留当前基本流程。只输入树的必要身份信息，名称必填，描述可选，颜色有默认值。创建成功才进入真实树页面；空树可立即新增节点，不自动填充虚假示例内容。

新建知识点分为内容、位置与关系两步：

1. 内容：左侧/上方显示当前草稿预览，右侧/下方填写内容。预览不在每次敲字时重播入场。
2. 下一步：同一个草稿预览缩合为待放置节点，进入所属树的画布。只改变表现，不生成第二份草稿。
3. 放置：拖动确定位置、选择必要关系。已有节点不重新排列；相机为新节点留出可操作区域。
4. 上一步：返回内容输入，名称、正文、颜色、位置与关系均保留。
5. 创建：校验并成功持久化后，草稿节点成为正式节点；保留同一视觉身份并进入编辑器选中状态。
6. 失败：草稿仍在，节点标记为未提交，不播放落成成功反馈、不导航离开。

页面“返回”退出创建回到树编辑器，与“上一步”分开。已修改草稿离开需保护。刷新或直接访问放置地址时，有可恢复草稿则恢复；没有则回内容步骤并显示一句“请先填写节点内容”，不得空白或创建空对象。

### 5.7 教学工作区：一个可操作的讲解现场

- 主要画面是当前教学对象，不是三张说明卡加一段长文本。TCP 切片使用大幅窗口变化示范与稳定输入区。
- 桌面主示范区约占 62%，当前问题/解释约占 38%；平板上下排列；移动端保持示范、题干、输入、操作的阅读顺序。
- 每次只突出一个任务：“预测下一轮”“说明原因”“验证”。不把整个教学流程的按钮同时暴露。
- 规则条件可折叠查看；必要单位和轮次始终清楚，不能为追求简洁隐藏解题前提。
- 讲解根据错误切换，示范状态与文案同步。动画可单步、暂停、回退，操作不依赖自动播完。
- 图形播放/单步控制贴近示范对象；提交/提示贴近题目，不组成页面副导航。
- 查看提示会被记录，不用恐吓文案阻止求助；独立验证中请求帮助后，转为有辅助任务，之后安排新的独立验证。
- 完成区展示“本次独立验证通过”及依据，不用爆炸特效和虚构掌握率覆盖结果。

### 5.8 练习与学习记录

练习负责独立应用与检查稳定性。题干、输入、提交占主体；答错后显示具体反馈，必要时提供“学习这个知识点”，并携带本次作答上下文。不能只跳到一个通用教学首页。

学习记录默认展示一条最近的真实学习过程和有依据的下一步，采用连续时间线/列表，避免四张指标卡挤满首屏。筛选只改变范围，不复制数据。

- 区分尝试、辅助完成、独立验证以及需要巩固。
- 可展开查看题目、帮助使用、判定理由、教学片段与后续任务。
- 演示数据显式标识，不与真实用户记录混记。
- 没有记录时只显示“还没有学习记录”，提供一个进入现有知识入口的动作。
- 删除不必要的鼓励段落，不显示无法说明算法意义的百分比。

## 6. 动画总谱与开场分镜

### 6.1 同一种行为使用同一种运动规则

| 行为 | 拟定时长 | 曲线与约束 |
| --- | --- | --- |
| 控件悬停/按下 | 120-160ms | 颜色/边界变化；按下最多缩至 .98，不移动热区 |
| 菜单打开/关闭 | 160-220ms | 透明度和 4-8px 位移，不弹簧过冲 |
| 预览出现 | 180-220ms | 固定位置渐显，内容不从屏幕外飞来 |
| 预览展开为详情 | 320-420ms | 共享容器布局变化，文字避免被缩放拉伸 |
| 选择新知识树 | 480-650ms | 同一展示区域，稳定投影尺寸 |
| 必要的小幅镜头调整 | 320-480ms | 平滑减速，无回弹 |
| 跨树/远距离运镜 | 800-1400ms | 根据距离限制时长，最多 1600ms |
| 创建预览进入放置 | 700-900ms | 明确锚点迁移，可逆 |
| 独立任务成功反馈 | 220-360ms | 证据状态更新，不遮挡内容 |

DOM 默认缓动为 `cubic-bezier(.22,1,.36,1)`，退出使用较短时长。相机使用平滑起止曲线，不做 overshoot、摇镜或运动眩晕式加速。

每个动画必须回答：是什么对象；从哪来；为何变化；到哪停；被打断怎么办；低动态模式保留什么。不能回答的装饰动画先不做。

### 6.2 开场不是加载条，分为两段

第一段是页面就绪后的“结构揭示”，默认约 1.2s，只播放一次；第二段是用户点击进入后的“空间展开”，默认约 2.6s。用户不点击时，页面已经可用，不持续自动转场。

“结构揭示”分镜：

| 时间 | 画面 | DOM 与交互 |
| --- | --- | --- |
| 就绪前 | 已有构图占位/简化结构，不能全黑等资源 | 品牌、标题和可用入口立即出现；无假百分比 |
| 0-240ms | 近景主体轮廓建立，亮度从低到最终值 | 标题直接可读，不逐字乱码解密 |
| 180-700ms | 同一结构的中景分支依次变清晰 | 文案区域轻微显现，位移不超过 12px |
| 560-1200ms | 远景关系与整体纵深完成，落在最终构图 | 主按钮一直可操作，不等 1.2s 才解锁 |
| 1200ms 后 | 稳定静止构图 | 无永久旋转、呼吸按钮、背景粒子循环 |

用户提前点击，立即终止揭示的剩余部分，从当前实际画面衔接进入段，不能先跳到预设初始镜头再重新播放。

资源准备和动画时长分开：场景未就绪时点击进入，只记录一次进入意图，保留可取消的准备状态，不能对空相机启动时间轴。出现致命加载错误或准备超过 8 秒时，显示“重试”和“打开知识库”这两个有明确用途的恢复动作；不让装饰素材阻塞 DOM 学习入口。场景就绪后从实际可见构图继续，而不是再强制等完一段加载动画。

### 6.3 点击“进入知识空间”的运镜分镜

取首帧实际相机与主体包围盒作为起点，不假设固定世界尺寸。整段复用 `SpatialExperienceShell` 中的场景身份。

| 时间 | 镜头与对象 | 标签、文案与状态 |
| --- | --- | --- |
| 0-180ms：确认 | 镜头基本稳定；当前主体的关键关系获得一次强调 | 按钮立即反馈；阻止重复进入请求；可见跳过入口 |
| 180-850ms：离开近景 | 观察中心沿真实分支方向平移，距离逐渐增大；偏航约 6-10° | 标题 220ms 内退出；场景仍是刚才的对象 |
| 700-1650ms：结构展开 | 近景成为整体的一部分，其他树在原有位置进入视野；总偏航不超过约 18° | 按屏幕密度逐层显示树名，不一瞬间铺满节点标签 |
| 1500-2200ms：找到落点 | 镜头朝默认总览或已保存目标缓慢落位，保留原主体可识别关联 | 路由在命名阶段点提交一次；顶栏出现，但未就绪的场景命令不接收输入 |
| 2200-2600ms：交接 | 到达安全构图，收束速度；不再继续慢漂 | 顶栏与拾取启用，焦点移到合理位置，进入 idle |

这些时间是编排基线，不用四个独立 `setTimeout` 驱动状态。使用一条受控时间轴和命名阶段，由完成/中断事件确认状态；同一事务最多导航一次。

不照搬“穿过星际隧道”“爆散再重组”。震撼来自近景尺度、结构显露、真实纵深和准确落点。动画的前后必须能认出同一个节点/分支。

### 6.4 跳过、中断和恢复

- “跳过动画”或键盘 Escape：终止时间轴，原子设置合法终点和可用 Universe 状态，不能停在半透明界面。
- 入场期间的拖拽/滚轮：取消剩余自动镜头，从当前位置交给用户；先完成必要状态交接，再接收控制，不把镜头弹回起点。跳过则直达最终构图，两者语义不同。
- Universe 自动聚焦期间，用户拖拽/缩放立即取得控制权，不在松手后偷偷恢复旧飞行。
- 当前入场事务发起的 `/` → `/universe` 是预期路由提交，继续执行剩余交接。只有用户发起的外部导航、壳卸载、目标失效等事件取消事务；过期回调无权把用户拉回 Universe。
- 页面隐藏：暂停非必要更新；重新可见时进入明确状态，不能补播一长串积压帧。
- 回访 `/universe`：恢复有效的选择和镜头，不重播开场。主动打开 `/` 可重新观看品牌开场。
- 低动态模式：无飞行、旋转、视差和逐层远近揭示，直接设置终点或使用不超过 120ms 的透明度交接，信息与操作完整保留。
- WebGL 失败：保留文字、搜索和知识库入口，显示静态结构/可访问列表，不阻止用户学习。

## 7. 全站连续性与相机契约

### 7.1 相机只由一个地方写入

复用 `CameraController`，保留 R3F 的渲染与现有质量管理。GSAP 如用于精确编排，只插值镜头意图的数值代理；每帧由相机控制器统一消费，禁止 OrbitControls、旧阻尼 effect、GSAP 同时覆盖相机。

Motion 只负责独立 DOM 叶子区域，不包裹场景内部再与 GSAP 争夺同一 transform。教学中的 DOM 输入与 SVG/几何播放区域也分开所有权。Anime 在本轮主要提供参考，不因为已安装就再接一套时间轴。

自动镜头与用户控制的切换顺序：停止旧动画 → 读取当前位置/target → 同步控制器状态 → 交出所有权。用事务编号丢弃过期完成回调。

### 7.2 可见目标不必飞行

在投影到屏幕后的安全区域中判断目标是否舒适可见：扣掉顶栏、打开的侧面板和各 24px 边距，检查目标完整包围框是否落在其中，并检查目标可辨识尺度。

- 在安全区域且尺寸合适：保持相机，只有选中反馈。
- 在屏幕边缘或被面板覆盖：最小幅度调整观察中心，不必拉回整树总览。
- 不可见或相距很远：才使用跨尺度运镜。

不能用“同一棵树永不移动”或“每点一个节点都飞一次”替代这个判断。

### 7.3 跨尺度参数与落点

- 镜头目标由对象包围盒、可用视口与投影计算，不为每个节点硬编码一个世界坐标。
- 距离在正数范围内插值，可采用 `exp(lerp(log(d0), log(d1), easedProgress))`；先校验有限值和正数。
- 观察方向使用稳定方向插值或四元数插值，避免横跨角度边界时转大圈；不引入滚转。
- 目标居中按扣除侧栏后的可用矩形计算，不通过永久移动整棵树补偿。
- 图谱节点位置不受悬停、选择、进入教学影响；只有用户编辑和明确的布局初始化可以写位置。
- 视口变化重算安全区，不重置选中对象和用户手工角度。相机 near/far 与控制距离随实际尺度校验，避免穿模或裁切。

### 7.4 节点预览进入教学

1. 点击节点，固定预览区成为选中对象的详情。
2. 点击“开始学习”，保存场景视图快照与知识点标识。
3. 以预览标题/节点标记作为视觉锚点，在 420-650ms 内过渡到教学标题/示范起始状态。
4. 主场景不再继续空闲绘制。离开空间壳时可以释放 Canvas，返回按快照恢复；不为了连续性永久保活全站所有场景。
5. 如果 DOM 与 WebGL 无法直接共享元素，使用最小、不可交互的过渡表示。新页面输入仅在自己就绪时启用；旧页面不能留透明热区。

页面切换不是“永远同时挂载两张完整页面”。只让有意义的共享壳或短暂视觉表示存续；实际表单、事件、焦点只有一份。

### 7.5 创建的对象身份

草稿在内容步骤就分配稳定的草稿标识。预览、放置与正式节点映射明确；实际持久化 ID 沿用既有生成规则，提交成功后只建立一次映射。

草稿的名称、颜色或内容改变，不重建整个场景。返回上一步按反向路径恢复预览布局，但不反向撤销已完成的数据保存。动画状态不是业务状态的存储地点。

## 8. 编辑与持久化：先修共同根因

### 8.1 已核实的问题链

此前只读复核和本轮源码检查确认，位置问题不是“完全没有持久化”：已有迁移/更新代码会保存坐标，自动布局也优先使用手工位置。

真正需要同时处理的是：

1. `CustomTreeCanvas` 的默认 `previewEdges = []` 引用不稳定，触发边集合和基础位置重算。
2. 基础位置 effect 会覆盖当前显示位置。
3. 编辑页保存拖动后，图缓存仍可能保留旧坐标。
4. 同一基础位置变化又触发整树居中和相机适配。
5. 旧内容草稿可能全量写回旧坐标。
6. 持久化异常被忽略时，界面可能假报保存成功。

当前返回热区问题也有明确根因：`WorkspaceHeader` 的返回按钮在 Grid 的 `1fr` 列中默认拉伸。前序浏览器实测 1280px 页面中，40px 左右的文字对应约 559px 的透明点击宽度。本轮没有重新实测所有页面，不将此数值泛化成所有返回按钮的问题。

### 8.2 四类状态只各有一个权威来源

| 状态 | 所有者 | 更新时机 |
| --- | --- | --- |
| 已提交位置/关系/内容 | 现有知识领域数据与持久化层 | 成功提交 |
| 拖动中的位置预览 | 当前画布的 ref/局部交互状态 | 指针移动；不每帧写持久化 |
| 未提交修改，包括内容草稿和保存失败的位置 | 编辑/创建工作区 | 输入、失败提交、明确保存/放弃 |
| 镜头/选择/面板状态 | 视图状态 | 用户操作与合法过渡 |

禁止根据数组引用变化全量重设位置。只根据真实的节点增删、权威位置变化和当前拖动状态做最小同步。新节点只补缺失位置，已放置节点不重新布局。

`[0, 0, 0]` 是合法坐标，不等于位置缺失。失败位置从“拖动预览”转为工作区待提交修改，至少持有节点 ID、预览位置、上次已提交位置和错误结果。直到保存成功或明确放弃才清除，纳入切节点、切模式和离开保护；旧的 pointercancel/失去捕获回调不能清掉已经结束的待保存事务。

### 8.3 一次拖动的完整契约

- Pointer down：识别节点和唯一指针，记录起点及已提交坐标，停止自动运镜；小于约 4px 的移动仍视为点击。
- Pointer move：用节点世界位置建立拖动平面；世界射线求交后转换到树的局部坐标。只接受有限的三元数，不混算世界与局部坐标。
- 拖动期间：捕获该指针，暂停画布相机操作，不选择别的节点；高频值放 ref/对象属性，不每帧 `setState`。
- Pointer up：使用最新有效位置，最多提交一次；持久化成功后同步权威数据与可视位置，不触发 fit/reset camera。
- Pointer cancel、失去捕获或卸载：终止拖动、释放捕获、恢复控制器；取消的拖动回到已提交坐标，不留卡住状态。
- 第二根手指不能接管第一个节点的拖动事务；多指相机手势需等待本次拖动结束或取消。
- 存储失败：保留未保存位置预览与重试入口，明确“位置未保存”；不可显示保存成功再刷新丢失。

位置保存与正文保存分开。保存文字/关系只提交对应字段，不把旧草稿中的 position 覆盖回去；取消正文编辑也不撤销已保存的位置。

### 8.4 保存、离开与并发最低保障

- 现有 `saveV9State`、`updatePoint`、`savePointDraft` 传播成功/失败结果。选择“保存并离开”时，只有成功写入才清除脏状态、显示成功并继续导航；选择明确“放弃修改”则清除本次未提交内容、恢复已提交位置后离开；“取消”留在原页。存储失败不能困住愿意放弃修改的用户。
- 保存前重新确认节点、所属树与关系目标存在，不用旧表单复活被删除节点。
- 数据校验和序列化在替换持久化内容前完成，错误时保留上一份有效数据。
- 另一标签页更新与当前脏草稿冲突时保留草稿、提示处理；不建设实时协作，只避免静默覆盖。
- 页面返回、切换页签、浏览器后退均覆盖脏草稿保护；没有修改不反复弹确认。关闭浏览器前的提示遵守浏览器能力限制，不能声称可以保证任何强制关闭都不丢失。
- 创建草稿需要跨步骤与普通刷新恢复；优先使用现有持久化能力的独立草稿字段/存储。草稿和正式对象分离，校验失败不能把半成品写进正式知识树。
- 本轮不新增完整撤销历史、版本云同步或自动整理产品功能。若已有显式整理功能继续保留，执行前说明范围，不在新增/选中节点时偷偷触发。

## 9. 教学闭环施工：HumanRAG 真正做什么

### 9.1 现有能力保留，缺口具体补齐

保留统一 `ContentRepository`、教学与练习状态机、作答记录、内容 schema、进度记录和已有失败终止机制。

当前需要改变的不是页面名称，而是以下实际行为：

| 当前缺口 | 本版目标 |
| --- | --- |
| 诊断后大量情况仍进入相同讲解 | 作答证据改变片段选择与示范内容 |
| 示例包含通用写作提纲，缺少完整过程 | 示范具有条件、学生预测、逐步结果和解释 |
| 为凑数量补入同分支误区 | 只使用相关且有依据的错因，不相关内容不兜底 |
| 错因文字依赖精确字符串匹配找 ID | 内容明确关联稳定 ID，文案变化不改变判断 |
| 独立检查可能重复已曝光题目 | 用未曝光任务与不同表达形式验证 |
| 正确/错误固定加减 confidence | 界面呈现事实性证据，不包装为掌握概率 |
| 练习补教入口只带 unitId | 携带题目、作答、帮助与恢复原练习所需上下文 |
| 记录更新与图谱显示未形成完整联动 | 当前知识点状态、待补教任务与建议同步更新 |

不要先为全部知识点接入大模型生成长文章。本版先把一个真实切片做深，其他知识点按实际内容能力展示，不冒充完成同等教学。

### 9.2 教学与练习分工

| 维度 | 教学 | 练习 |
| --- | --- | --- |
| 核心目的 | 找到困难并帮助理解 | 独立运用并检查稳定性 |
| 系统主动性 | 根据证据选择解释、示范、追问 | 根据范围与历史安排任务 |
| 帮助 | 可分层提供并逐步撤除 | 默认独立；求助后显式转补教/辅助 |
| 答错后的行为 | 判断错因或继续区分，改变教学 | 记录结果并提供针对性学习入口 |
| 完成依据 | 在撤除帮助后完成新的验证 | 本次真实作答结果与范围 |
| 不能使用的替代物 | 播放完动画、读完文章 | 反复刷已曝光答案制造“掌握” |

两者共享题目读取、答案评估和证据记录。不要复制一套教学判分和一套练习判分，导致同一答案出现不同结果。

### 9.3 最小检索实现

本版使用现有知识 ID、先修关系、错因 ID 与内容片段元信息进行可解释的本地选择，不增加向量数据库。

检索输入：当前目标、知识点、最近作答及过程、已确认/待确认错因、先修缺口、已看内容、已曝光题目。

内容片段至少包含：稳定标识、所属知识点、适用错因、前提条件、实际内容、关联示范、来源与内容版本。优先复用现有 `TeachingStep` 和内容块，不建立独立 CMS。

选择顺序固定且可测试：

1. 确认当前知识点和内容确实存在，排除失效引用。
2. 根据已确认错因形成候选片段，并检查该片段的必要前提。
3. 若证据显示缺少前提，先补直接必要的前置内容，再继续处理原错因；不沿整张图无限扩展。前提满足后返回对应错因片段。
4. 错因不确定，先给一个能够区分候选原因的短追问。
5. 没有匹配片段，回到当前知识点的基础讲解；仍没有内容，则坦率显示暂未提供完整教学。
6. 排除已完整展示的独立验证任务；同优先级使用稳定顺序，便于测试复现。

记录选中的片段 ID 和选中理由。用户界面最多出现一句具体说明，例如“先看门限前后的变化”，详细依据收进记录，不常驻解释整个算法。

### 9.4 错因不是从错误答案随意猜出来的

- 选项/步骤可以关联错因 ID，但单个错误答案默认只是候选证据。
- 两种原因可能产生同一个答案时，追问关键一步，不直接贴确定标签。
- 允许 `unknown`/原因待确认；未知不是流程异常。
- 自由文本不能只与一条标准答案做字符串相等比较，就宣称理解错误。当前本地实现优先采用可客观评估的数值、步骤与理由选择；开放解释可保存为反思，不假装已完成可靠自动评分。
- 引用“模型评估”之前，必须真的有模型调用、错误处理与验证。本轮不新增这项依赖。
- 同一问题的反馈解释、错因标识和后续片段要一致，禁止显示 TCP 错误却补教线程或握手主题。

### 9.5 教学状态机

```text
ready → diagnostic
          ├─ 已能解释 → independent-check
          ├─ 证据不足 → clarification → targeted-teaching
          └─ 具体困难 → targeted-teaching
                                         ↓
                                guided-practice
                                         ↓
                                independent-check
                                  ├─ 通过 → evidence-summary
                                  ├─ 未通过且可补教 → targeted-teaching
                                  └─ 补教耗尽/无新题 → paused-with-next-step
```

这是对现有状态机的收敛与修正，不另造一个通用工作流引擎。

- 每个分支都有可达出口，无死循环。
- 保留当前最多两轮补教的边界；仍未通过，结束本轮并保留“需要巩固”，不循环到用户猜对。
- 没有未曝光新任务时，不伪装完成。提示“本轮没有新的验证题”，保留记录，允许停止。
- 已具备能力的用户可以跳过示范进入新任务，不强制所有人走统一八步。
- 当前 schema 对步骤数、误区数、诊断题数有固定下限。本切片允许调整这些数量型限制，以内容引用有效、必要验证存在、路径可达且可终止的检查替代；不能为了满足 `.min(3)` 塞入无关误区，也不能把所有校验直接删除。

## 10. 第一条完整教学切片：TCP 慢启动

### 10.1 学习目标与科学边界

目标：用户根据给定规则预测窗口变化，并解释慢启动到拥塞避免的转换。

本切片明确使用逐 RTT 的简化教学模型：

- `cwnd` 以 MSS 为单位，初始值和门限由题目给出，不声称所有真实 TCP 都从 1 MSS 开始。
- 第 0 轮为初始状态；第 n 轮为完成 n 个 RTT 后的状态。
- 门限以下，每轮窗口翻倍；达到门限后，下一轮增加 1 MSS。
- 首版只使用翻倍能恰好达到门限的参数，即 `ssthresh / cwnd0 = 2^k`，其中 k 为非负整数。k=0 表示初始即达到门限，下一轮直接增加 1 MSS。
- 交互参数域：初始窗口为 1-8 的整数 MSS，门限为 1-64 的整数 MSS 且满足上述比值，轮次为 0-8 的整数。拒绝负数、零窗口、NaN、Infinity、小数轮次和不满足比值的组合；不默默四舍五入输入。
- 不包含丢包、超时、快速恢复、接收窗口限制、延迟 ACK 与实际 ACK 时序。规则入口能查看这些假设。

真实 TCP 的窗口调整与 ACK 等条件有关。不得把此离散模型宣传成完整 TCP 协议仿真；正式内容应对照 [RFC 5681](https://www.rfc-editor.org/rfc/rfc5681.html) 核验，并标出本例的教学简化。

### 10.2 任务与题目隔离

以下是施工用明确样例，不是当前题库质量已经达标的声明。

| 用途 | 参数与题型 | 期望行为 |
| --- | --- | --- |
| 首次诊断 | 初始 1，门限 8；填写第 1-4 轮并选关键理由 | 序列为 2、4、8、9；识别倍增、初始轮次和门限转换 |
| 示范 | 初始 2，门限 16；先预测再逐轮播放 | 2 → 4 → 8 → 16 → 17，同步解释条件 |
| 引导 | 初始 4，门限 16；只在需要时提示判断阶段 | 4 → 8 → 16 → 17，记录帮助使用 |
| 首次独立任务 A | 初始 3，门限 12；预测第 4 轮并说明使用的规则 | 第 4 轮为 14；理由与过程均符合规则 |
| 首次独立任务 B | 给出第 0-4 轮分别为 5、10、20、21、22 的观测表，判断门限达到时刻和随后变化 | 第 2 轮结束达到 20，之后按每轮 +1 |

为两轮补教后的复测另备两对未曝光参数与任务，不能只换题目 ID。至少覆盖“正向预测”和“由观测反推阶段”两种表达。

诊断、讲解示范、引导与独立验证有明确用途标签；相同语义题即使重新排序选项也算已曝光。独立题的参数、正确答案和解题过程不能出现在此前动画示范或提示中。

曝光的最小判据包含模型/内容版本、初始窗口、门限、所问轮次或观测区间、任务类型，不以题目 ID、随机种子或选项顺序作为身份。相同答案数值不等于相同任务；通用方法已经教过也不等于题目曝光。示范、提示或可调参数操作一旦实际揭示保留任务所需的具体结果，登记该结果曝光，保留题作废并更换；仅换一种问法不能绕开已揭示结果。若无新题则正常停止验证。

### 10.3 错因分流

| 候选困难 | 区分性证据 | 对应教学画面 |
| --- | --- | --- |
| 把翻倍当固定相加 | 连续两轮增量判断与理由选择 | 保留用户预测轨迹，与正确增长轨迹对照，显示差异从哪一步开始 |
| 把初始状态算为第一轮 | 指认“第 0 轮”和一次 RTT 后状态 | 时间轴固定初始锚点，移动轮次标记，不另加大段文字 |
| 门限后继续翻倍 | 门限相等时对下一轮的判断 | 门限线与当前窗口相遇后，规则标记切换，再播放下一轮 |
| 不清楚 MSS/窗口含义 | 必要的概念区分追问 | 先补最短前提，避免直接继续计算题 |
| 原因无法确认 | 数值和理由矛盾或不足 | 显示短追问；不能随机分配前三种之一 |

纠错内容只处理相应困难。诊断全对且过程充分者，不强迫看这些纠错画面。

### 10.4 示范舞台的具体画面

- 采用 SVG/HTML 或现有图形能力绘制真实数据，不新增一个 WebGL 场景。几何图形是教学内容，不能用静态生成图片替代可计算关系。
- 横向为轮次，纵向为窗口大小；旁边保留当前轮窗口单位块。轴、单位和初始状态不能省略。
- 固定状态用中性实线，用户预测用轮廓/虚线，正确演变用强调色。不能只依赖颜色区分。
- 达到门限时保留一条明确参考线，标签为“门限 16 MSS”等实际参数，避免“知识跃迁”“激活思维”一类拟人文案。
- 每一轮由用户先预测，再触发演示。单轮播放约 650-900ms：输入锁定 → 对应已有窗口形体展开 → 新状态稳定 → 数值与规则更新。
- 只在整个概念需要时比较两条轨迹，不同时出现四张小图和重复指标。
- 播放、暂停、上一状态、下一状态在图内固定控制区；禁用态有原因。拖动进度不改写学习证据。
- 低动态模式直接替换为下一轮离散状态，并保留前后数值对照。关键教学信息不依赖看到运动过程。
- 允许改变的参数只在预先校验范围内。重置参数会清空当前示范预测，不清除已经提交的独立证据。

### 10.5 从示范走向独立

引导阶段的帮助由强到弱：先提示判断阶段；随后只提供可主动展开的规则；最后独立验证不默认展开规则。

独立任务请求提示时，立即标记为辅助作答，正常帮助用户完成。之后用新的任务验证，不能把有帮助的一次正确升级为独立通过。

本切片完成标准：两项未曝光任务均在无帮助条件下完成，包含正向应用和阶段解释。这个标准是本产品对“本次验证”的操作定义，不是已验证的长期学习成效或统计掌握概率。

每轮验证开始时预留一对新任务，正向预测和观测判断各一项。同一轮两项均独立通过才满足完成条件；不得把第一轮通过的 A 和复教后另一轮通过的 B 拼成一轮通过。任一失败或求助，该轮不通过，保留已经获得的事实记录，进入必要补教后重新安排一对。尚未展示的预留题不算曝光，可重新进入候选池。

一次“补教完成后重新进入独立验证”消耗一个补教重启名额，最多两次。一个补教阶段内多次点击提示不重复扣名额；独立任务中求助会使本轮转为辅助任务，并在之后重启验证时计一次。第三轮仍未通过就结束本次会话，不能另开隐藏计数继续循环。

## 11. 学习证据与推荐回写

### 11.1 最小数据补充

在现有记录与 schema 上增量补充。字段归属先检查能否从题目/会话推导，能推导的不要重复持久化。

| 信息 | 用途与兼容规则 |
| --- | --- |
| 题目/内容版本 | 区分修改前后材料；旧记录保留未知版本 |
| 任务家族与语义变体签名 | 检测同题换 ID、选项换序或相同具体解题结果已曝光，不因答案数值碰巧相同误判 |
| 会话与尝试标识 | 防止双击提交、完成回调重放导致重复写证据 |
| 帮助级别与提示次数 | 区分独立、提示后、示范后、旧记录未知 |
| 是否已曝光 | 按用户与任务内容计算，不能仅看本次会话 |
| 作答过程/理由结果 | 支撑错因判断，保留不确定性 |
| 选中的教学片段及依据 | 证明为什么教这部分 |
| 原练习恢复上下文 | 会话、范围、当前位置与当前未提交输入 |

旧记录不含帮助和曝光信息时，标记“未知”，不能默认迁移成独立完成。题目版本变化不回写篡改旧记录，也不把旧成功结论自动用于更新后的新内容。

版本号必须能够解析回当时的不可变内容；若现有存储做不到保留历史版本，则在证据中保存最小题面/参数、用户选择值、标准判断依据快照。只存选项 ID 再用新题目解释旧选择不合格。未知旧版仅展示可确定的原始记录，不套新版答案重新判分。

### 11.2 状态展示

界面使用事实性状态：

- 尚未验证：没有满足本切片条件的证据。
- 需要巩固：最近任务暴露困难，尚未由新的独立证据解决。
- 辅助下完成：依赖提示/示范完成了对应任务。
- 本次独立验证通过：满足本切片的独立任务规则。

状态附日期和必要证据入口，不显示 `confidence × 100%`。现有数字字段为兼容可暂保留，但不再以“掌握概率”对用户解释。

学习状态不是严格只升不降的等级条。后续新的失败证据可以提示需要巩固，同时保留之前通过的事实。

### 11.3 回写范围

一次合法提交只写一条对应证据，聚合更新按相同幂等标识处理。

- 更新当前知识点状态与最近记录。
- 确认解决的错因才关闭对应补教任务，待确认或仍错误的不关闭。
- 更新同一知识点在 Universe、树页面和学习记录中的展示。
- 推荐下一步时优先尚未解决的必要前提，再考虑用户目标相关任务。
- 不将一个节点通过推断为整棵树或相邻节点全部掌握。
- 不把练习中已经展示解析的原题重做当成新的独立证据。
- 写入失败保留待提交结果，显示“记录未保存”，允许重试；不能重复加分或假报完成。

### 11.4 练习补教与恢复

进入补教前保存当前练习位置、已提交答案、未提交输入和筛选范围。携带当前错误及判定状态，不只携带 `unitId`。

补教完成后，“继续原练习”恢复该会话，原错误仍是历史错误，不自动改成正确。若需要验证，安排一个新任务；原题可供回顾但不承担新证据。

用户从顶栏返回所属树，原练习保留可恢复状态，不强行把用户拉回练习。切换用户身份时不能混用另一个人的会话与证据。

## 12. 文案清理规范

### 12.1 保留什么，删除什么

保留名称、字段标签、任务条件、单位、真实状态、必要错误、危险动作后果、来源与无障碍描述。

可见文案尽量短，但不能删掉题目条件、数据未保存提示与删除后果。详细教学解释根据需要展开，不以“页面简洁”为由把真正教学也删掉。

## 14. 性能、可访问性与失败体验

### 14.1 画质不是唯一档位

沿用现有 quality/balanced/performance 体系。Windows 的保守初始策略可保留，随后结合真实帧耗时与用户选择，不因操作系统名称永久判定设备能力。

参考设备由实施时记录实际 CPU/GPU、浏览器、窗口和 DPR，不能只写“在我电脑很流畅”。至少包含一台 Windows 集显/普通笔记本、桌面主测试环境与一台真实触屏设备；暂时没有设备则标记未验证。

### 14.2 拟定性能预算与测量方法

| 指标 | 验收基线 | 测量场景 |
| --- | --- | --- |
| 常用交互反馈 | 点击/按下约 100ms 内有可见反馈；不能等长动画完成才响应 | 打开预览、输入、拖动开始、提交 |
| 桌面空间流畅度 | 30 秒脚本中中位 FPS ≥55，P95 帧耗时 ≤25ms | 1080p、当前完整知识库、balanced/quality 分别记录 |
| 保守档可用性 | 中位 FPS ≥30，P95 帧耗时 ≤50ms | Windows/移动保守档，同一操作序列 |
| 编辑跟手 | 无超过 100ms 的可感知输入停顿，松手无跳跃 | 拖动、改变关系、保存并再选择 |
| 布局稳定 | 初始加载 CLS 目标 <0.1；输入区不随示范播放跳动 | 字体、侧栏、图形和题干加载 |
| 首屏内容 | Lighthouse 移动模拟条件下 LCP 目标 <2.5s | 生产预览，记录条件；不能拿本地热缓存代替 |
| 真实交互指标 | 有实际会话数据时再评估 INP，目标 <200ms | 不用一次 Lighthouse 报告宣称已验证线上 INP |

这些是待测目标，不是当前项目跑分。性能未达标时先减少效果、标签与像素预算，不降低题目可读性、删除输入校验或取消退出入口。

### 14.3 渲染与资源纪律

- 在现有像素/DPR 预算上迭代，不默认以物理最高 DPR 渲染全屏。
- 节点、边与材质尽量批量/实例化；不因一点悬停重建整张图。
- 停止无意义空闲运动；无变化时使用现有按需/降频策略，活动动画显式请求渲染。
- 场景编排不新增第二条永久 RAF；定时器、GSAP context、Motion 动画、观察器、事件、几何和材质均有明确释放责任。
- 同一展示区域切树不能短时出现两个完整 WebGL 上下文。
- 用户阅读、输入、答题时，后台空间停止绘制；页面隐藏停止非必要工作。
- 按路由加载教学/编辑功能；不可为了开场预加载全部题目、所有编辑器和所有动画库。
- 避免大面积实时模糊、动态噪点和整屏滤镜；文字层不做不断变化的 filter。
- 先准备可用构图与必要 shader；非必要资产后载。就绪失败给出可继续学习的路径，不以全屏 loader 无限等待。

### 14.4 无障碍与键盘

- Tab 顺序随视觉任务顺序，焦点始终可见；关闭菜单/预览/对话框后返回触发控件。
- 空格/回车可操作真实按钮；不把所有交互写成只有鼠标事件的 div。
- 模态工具打开时正确约束焦点，背景不可点击；Escape 优先关闭最上层临时 UI，不穿透触发页面返回。
- 场景节点具有可通过搜索/目录访问的语义等价入口。触屏不依赖悬停，小节点通过合适拾取区域和列表消歧，不重叠扩大所有热区。
- 支持现有快捷键；补充搜索快捷键时，输入框内不抢占正常编辑命令，macOS 与 Windows 的修饰键正确。
- `prefers-reduced-motion` 影响所有连续运镜和位移动画，不能只关闭 CSS，遗漏 WebGL 时间轴。
- 状态变化用文字/形状共同表达；教学图提供当前离散数据和文本解释，可被辅助技术理解。
- 200% 缩放、窄屏、长中文名称、长代码行均不遮挡关键按钮。

### 14.5 必须设计的非理想状态

| 状态 | 行为 |
| --- | --- |
| 数据读取中 | 保持最终区域尺寸的占位；不重复入场闪烁 |
| 内容缺失 | 说明当前知识点暂无完整内容，返回该树；不生成虚假教学 |
| 节点/树已删除 | 取消过期操作，回到仍存在的最近父级并解释 |
| 搜索无结果 | 保留查询与范围，显示简短无结果状态 |
| 存储失败 | 保留输入/结果，显示未保存，提供重试 |
| 草稿冲突 | 保留本地草稿，明确冲突，不静默覆盖 |
| 没有新验证题 | 结束本轮验证，保留尚未通过状态 |
| WebGL 不可用 | 保留知识列表与学习入口，提供轻量展示 |
| 全屏拒绝 | 保持原布局与状态，简短说明失败 |
| 动画被打断 | 转到合法状态，释放锁和事件，不留半可用页面 |

## 15. 分批施工顺序与停止条件

不要把本文件一次性交给开发后等待所有页面完成。每批都有可独立检查的产物，前批否决的问题不能扩散到后续页面。

### G0：基线与变更边界

行动：记录当前关键页面截图和录屏、当前已有测试结果、数据备份/迁移样例、实际设备信息、改动文件范围；复核参考许可。

交付：基线记录、待修缺陷清单、参考对应清单。

停止条件：能够区分原有问题与新增回归；现有用户数据有保护方式；不假设脏工作区属于本次修改。

### G1：先确认三个关键画面与一条运镜预演

行动：按第 3-7 节制作以下有限设计产物。此阶段只做确认方向所需的画面/局部原型，不铺开所有页面。

1. 开场完整构图：静止状态与关键近景，验证主体尺度、中文排版和材质。
2. Universe 选中节点状态：顶栏、固定预览、标签密度与空间安全区。
3. TCP 教学状态：大示范对象、预测输入、帮助与独立验证的区别。
4. 一条低成本运镜预演：开场近景 → 图谱总览 → 节点预览，能检查连续性与节奏。

至少提供 1440 × 900、1280 × 800、390 × 844 的布局；运镜预演额外给低动态版本。使用真实内容和实际节点身份，不以假界面截图替代。

停止条件：用户确认这三张画面的视觉方向及预演节奏。在确认前，不将新风格大面积铺到编辑、练习和记录页面。此处是明确人工验收门，不以“符合 token”自行通过。

### G2：共享交互与数据稳定基础

行动：合并顶栏，统一父级返回，修复返回热区、拖动回弹、坐标系、相机重置、旧草稿覆盖位置和保存失败反馈。

交付：一套真实顶栏；完整编辑回归录像；单元与浏览器回归检查。

停止条件：第 16 节 NAV、EDIT、DATA 类关键用例通过。尚未美化的页面可以保留，但不能继续存在双层导航和数据回退。

### G3：空间视觉贯通

行动：落地已确认的开场、Universe、节点预览、树展示与镜头状态，完成从开场进入并访问一个真实知识点的路径。

交付：正常/跳过/打断/回访四种录屏，关键静止截图与初步性能记录。

停止条件：对象可追踪、没有跳镜和残留热区；知识库切树清晰居中；用户输入可接管镜头；Windows 保守档可用。

### G4：完整教学切片

行动：完成 TCP 内容核验、互动示范、诊断分流、辅助记录、未曝光验证、练习补教与证据回写。

交付：两个不同错误进入不同教学的真实录屏；一条无需补教的快速通过路径；一条失败终止路径；内容与规则测试。

停止条件：能从记录解释“为什么教这部分、是否用了帮助、凭什么说本次通过”，且图谱与记录一致。不要求先完成所有知识点同等深度内容。

### G5：其余页面统一

行动：把已确认视觉语言和动效规则应用到创建、编辑、树学习/题库、练习和记录；逐页删冗余文案；补足移动和异常状态。

交付：页面对照图、完整创建/编辑流程、内容与按钮清理清单。

停止条件：全站没有另一套按钮系统、第二排导航、重复教学页面、来源式错误返回或无退出创建流程。

### G6：独立验收与参赛呈现

行动：进行静态美术、动态、交互、教学真实性、数据安全、可访问性与性能的独立检查。整理可复现演示，不篡改产品流程。

交付：验收报告、真实演示路径、性能/设备记录、素材与引用清单、已知限制。

停止条件：所有 P0 项通过，P1 项解决或由用户明确接受；具体画面获得确认。测试数量、截图数量和成功构建不能替代视觉与教学验收。

### 执行时的版本控制

每个工作包形成可审查的小提交；内容修正、导航/数据根因与纯美术尽量分开，便于定位回归。不擅自提交其他人的改动。

复杂独立问题可按项目规则由两个子任务分别研究，避免同时修改共享顶栏、token 或 store。需要并行开发时先明确文件所有权与分支/worktree 边界；当前写方案不创建开发分支或工作树。

## 17. 参赛演示怎样证明产品价值

用户尚未报名，项目先完成，再依据届时正式规则与真实成果选择赛道。本文件不把网站审美奖项标准混同于 iTeach 评审标准，也不将某学校内部预选评分当作省赛最终评分。

演示聚焦四个能现场验证的事实：

1. 用户选择一个具体目标，系统找到相关知识范围，而不是展示全部内容。
2. 两种不同作答导致不同讲解与互动示范，决策依据可展开查看。
3. 用户在帮助撤除后完成没看过的新任务，系统区分独立与辅助证据。
4. 下一步建议、知识点状态与学习记录真实同步。

建议演示主线约 4-6 分钟：

- 0:00-0:25：开场与进入知识空间，展示统一的视觉品质。
- 0:25-0:55：选择与 TCP 相关目标/知识点，显示范围和入口。
- 0:55-2:10：一次真实错误、区分性追问、对应互动示范。
- 2:10-3:20：撤掉帮助，完成新任务与解释。
- 3:20-4:10：回到图谱和记录，查看实际证据与下一步。
- 余下时间：对照另一种错误分流，或展示创建/编辑稳定性与技术边界。

演示可以使用明确标识的独立样例账户/数据集，但必须与真实记录隔离，不能通过后台预先把结果标为成功。演示计时只是讲解组织建议，不要求产品强制用户在这些时长内完成。

现场材料包括：产品问题、核心流程、实际实现范围、技术/教学依据、可复现案例、设备性能和已知限制。暂未做用户研究就明确未做，不编造学习提升百分比、用户量或实验结论。
